## Image message boundary correction

At baseline 7be9a791b, the Markdown image grant route used a hardcoded OC1 message URL before host filesystem authorization. It lacked family/profile admission and retired-result checks. The correction reads a projected message through kernelOperations.getMessageView and checks both kernel identity and backend family/revision after asynchronous work. CAgent and unaccepted Legacy are refused before directory, backend or filesystem work. The VS Code filesystem bridge retains its deliberate 501 response.

Exact-source matching, code-fence exclusion, file signatures, workspace/temp-root restrictions and per-image failures are preserved. Focused tests cover both real SDK routes against a loopback fixture, missing-message 404, upstream-failure 503, admission refusal and retirement during directory validation, message reading and file inspection. These fixtures establish the route contract, not live upstream or packaged-runtime acceptance. No transport, cache or retry layer was added. Verification and final source fingerprints are recorded in artifacts/int02-r1-image-evidence.json.

Runtime scope: Web and Electron use the shared host route; hosted and Capacitor mobile use their selected host; VS Code retains its explicit unsupported response. Real CAgent mapping remains CA-03. Neutral consumer migration remains R6, but an unguarded existing escape is not accepted merely because migration is later.

The completed boundary review covers HTTP route entry, asynchronous retirement, event delivery and managed plugin preparation. The reviewed plugin and agent-tool entry points refuse a non-OpenCode family and the unaccepted Legacy profile. Plugin routes capture family/revision and kernel identity across directory resolution and before mutations. The global event hub owns kernel/epoch rejection when committing events; the watcher checks current family/revision and Legacy admission, and its standalone reader checks the attached kernel. Git worktree disposal captures family/revision and kernel identity before awaiting and rechecks them before disposal. Production composition supplies the selected host to these guards and wires the shared hub into the watcher. The agent-tool callback dispatches by OC1/OC2 after family/profile admission; managed preparation has a family/revision lease, while generation probing alone does not disable all Legacy plugin preparation.

The VS Code agent proxy still returns 501 before forwarding. Adapter binding remains planned, as verified by `packages/vscode/src/bridge-proxy-runtime.ts` and its tests. The current review record and fingerprints are in `artifacts/int02-r1-boundary-evidence.json`; preserve earlier evidence counts and their original scope. R1 remains open for the remaining queue, browser-closed and connection-switch acceptance journeys. Exact Legacy conversation belongs to R2, consumer migration to R6, and packaged acceptance to R7. The closed browser journey must verify that owned pending activity and queue intent survive browser closure without claiming an in-flight request resumed. The final boundary run passes 171 tests across 14 files, including same-target watcher restart and eight real Git/loopback-HTTP disposal cases. These contracts do not prove live CAgent or packaged-host behavior.
