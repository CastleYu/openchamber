# ACP parity review: OpenCode commands, server APIs and shared UI

## Review outcome

The current ACP integration covers the conversation path and agent-advertised ACP controls. It does not provide a compatibility layer for OpenCode's entire command and server API. Existing app-owned features remain available only where their callers use OpenChamber services directly. OpenCode-owned provider, MCP, skills, LSP, queue, schedule, upgrade and session-management semantics need their original owner or an explicit ACP/host contract; exposing an existing UI control cannot create that behavior.

The source basis is the current uncommitted worktree at review time. The dual-kernel inventory is a feature map, not proof that every historical OpenCode feature exists in this current branch. ACP evidence comes from `packages/web/server/lib/acp/`, its UI adapter and current docs. Fixture coverage is not external-agent acceptance.

## Grok 4.7 review

The CLI help was read before invocation. Exact review command:

```powershell
& 'C:\Users\74756\.grok\bin\grok.exe' --model grok-4.7 --reasoning-effort high --no-subagents --output-format plain --prompt-file '.codex-temp\acp-grok-parity-prompt.md' *> '.codex-temp\acp-grok-parity.log'
```

The model returned a substantive one-turn review (`grok-4.7-build`, reasoning effort requested as high, one model call). Raw stdout/stderr and the complete answer are retained in `.codex-temp/acp-grok-parity.log`. The CLI exited 1 after Grok failed to save its chat because its user data reported `No space left on device`; the model answer had already been emitted and captured. The unprivileged attempt exited before session creation because Grok could not write its own user-level lock. The elevated exact rerun completed the model call. No credentials were read, copied or printed. No source or global Grok configuration was changed.

Grok's strongest findings were the stdio/remote callback boundary, the distinction between app-owned terminal and agent terminal, the limits of UI-only queue controls, and the importance of separating app-local links from OpenCode sharing. Source checks confirm those boundaries. Two Grok conclusions need correction against ACP v1 and current source:

1. `session/delete` is a standard v1 method gated by `sessionCapabilities.delete`; current runtime correctly calls it only when advertised. Local hiding is the fallback. Grok's suggestion that deletion is outside v1 is wrong.
2. ACP slash commands are advertised in `available_commands_update` and deliberately sent as ordinary `session/prompt` text. This is a defined v1 flow, and current ACP autocomplete supports it. The limitation is that it does not make OpenCode's unadvertised built-ins or command catalog portable.
3. OpenChamber has same-instance session/message links in `lib/sessionLinks.ts`; Grok was right that these are not public `session.share` shares. The table separates them.

The Grok response initially marked attachment parsing unverified. Source inspection in this review confirmed the exact media capability checks and the remote local-file rejection described above. No real external ACP agent or device was exercised by this task.

The parent task independently completed a real OpenCode 1.19.0 ACP acceptance with two model-backed sessions, tool read/write approval and denial, command cancellation, restart/resume and history load without local transcript cache. The Windows scoped-list defect above is from that live run; it is separate from the fixture and source evidence in this audit.

## 中文摘要

ACP 已覆盖会话、流式对话、代理声明的配置/斜杠命令、权限、elicitation，以及本地 stdio 的受限文件与终端回调。会话删除本身是 v1 标准能力，但必须由代理声明。OpenChamber 同实例链接不等于 OpenCode 公共分享。OpenCode 的 provider、MCP/skills 管理、LSP、分叉/revert、队列/定时任务和服务器管理不能只补 UI；需要原后端或明确的 ACP/主机契约。remote ACP 不获得本机文件和命令权限，独立 VS Code 仍不支持 ACP。

本轮调用了 Grok CLI `grok-4.7` high，并捕获到完整模型回答；CLI 在保存会话时因 Grok 用户数据目录报磁盘配额不足而以 exit 1 退出。模型回答可见于原始日志，状态不应标成干净成功。检查范围是当前未提交源码；没有运行真实外部 ACP agent 或设备验收。

主代理另外报告：真实 OpenCode 1.19.0 完成双模型会话、工具读写审批与拒绝、停止命令、重启恢复和无缓存历史加载；测试同时发现 Windows 本地项目路径使用斜杠时，按项目 scope 的历史发现为空。主代理正在做最小修复。remote cwd 必须保留服务端路径，不能照搬本地 Windows 规范化。
