高风险误判：

1. **第 4 行标成 IMPLEMENTED 是错的。** 声明的命令被当成普通提示文本。v1 没有命令 RPC，`/undo` 也不在可移植集合里。
2. **第 1 行的 IMPLEMENTED 过宽。** 跨重连/重启还在的是主机记录。代理可以只支持 resume，且不交还更早转录。
3. **第 8 行把分享链接和分叉/revert 捆在一起。** 分叉、按消息分叉、revert/unrevert、会话 shell 都不是 v1 方法，UI 隐藏是对的，只做 UI 也不安全。OpenCode share API 同样不是 ACP。主机永久链接若要做，是 OpenChamber 自己的功能；基线没有证明它已经存在。
4. **第 13 行如果合成“文件和终端已支持”，会授权错误的访问。** 用户终端是应用 PTY。代理 `terminal/*` 与 fs 读写只在本地 stdio、会话 cwd 内。remote 代理不能拿到这两组回调。门闩必须同时看 `isAcp()` 和 stdio/remote。
5. **第 14 行的“拦住”只覆盖作曲区。** 其它调用方仍可能送出队列、并行或合成上下文。只做 UI 的队列没有每个代理的队列语义，不安全。定时提示没有 ACP 对等实现。
6. **第 10、11 行。** `mcpServers` 是建立会话时的输入，不是 MCP 管理。主机 MCP API 管不到远端代理。代理命令也不是 skills 目录。
7. **第 16 行的命令列表**是代理声明的命令，不是 OpenCode 命令目录。SSE 实现不等于外部代理已被验收。
8. **第 5、6、15 行的权限。** 选项 ID 必须原样返回。自动接受、OpenCode question/reject、会话目标都是另一套契约。隐藏是对的；在 UI 里做映射是错的。
9. **共享 UI 不等于 VS Code 有 ACP。** 上述状态只覆盖走 `packages/web` ACP 后端的运行时。
10. **第 7 行解析器未在本轮核对。** 在读到 `runtime.js` 解析器之前，不要把附件范围扩到本地文件、资源链接或未声明的媒体类型。
