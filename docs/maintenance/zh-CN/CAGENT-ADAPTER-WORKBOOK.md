# CAgent 本地适配工作手册

> 中文审阅稿：本译文供审阅使用，英文文档是实现交接的规范版本。

状态：规划模板，2026-10-08。在 CA-02 交付 [CAgent 规范](CAGENT-INTEGRATION-SPEC.md)中说明的可执行工具包后使用。本文不包含猜测的 CAgent API 路径。以下所有占位内容都须根据本地文档和证据填写后才能确定。

## 交付到环境中的任务包

架构负责人必须在冻结的应用/契约修订版下同时提供以下材料。若 CA-02 只承诺提供文件或可执行命令，却未实际交付，则验收失败。

| 材料 | 必需内容 |
| --- | --- |
| START-HERE | 准确的离线设置和检查命令、支持的工具链、工具包/应用摘要、契约版本、文件白名单和恢复步骤。 |
| 适配器工作区 | 默认禁用且可编译的骨架、生成的操作常量、类型化请求/结果、受限传输/认证钩子和明确注册点。无需编辑整个仓库。 |
| 契约参考 | 每项操作一页简明说明，列出所需语义、成功/失败/不支持示例和相关功能 ID。 |
| 映射与能力模板 | 根据下表填写并通过schema 校验的记录、生成的覆盖报告，以及功能受阻原因。 |
| 扩展模板 | 固定的表单/结果词汇、带命名空间的操作常量、处理器桩和负向测试。 |
| 验证工具包 | 受保护的参考夹具和测试、示例适配器、离线夹具运行器、隔离的真实运行检查运行器、变更文件及功能依赖检查。 |
| 任务包与报告 | 每个任务包包含一项操作，并按依赖关系排序；可恢复的结果记录、本地证据报告和产物清单。 |

工具包命令在必需检查失败时必须返回非零状态，并生成简明的机器可读结果，其中包含操作 ID、预期/实际结果、证据引用和下一步。输出不得包含原始秘密或用户载荷。本地 Agent 只接收相关任务包和契约页，不把全部仓库说明塞进一个大提示词。

## API 证据收集

本地维护者在环境内提供端点/认证引用和 API 文档。Agent 为每项映射记录文档修订版、已知时的服务器构建版本及准确章节。源文档和样例保留在本地；无需外部上传。外部交接只能包含获准的脱敏覆盖摘要。

| 映射字段 | 填写规则 |
| --- | --- |
| 操作 ID / 调用方 | 选择生成的常量和固定功能注册表；绝不自行发明核心操作 ID。 |
| 证据 | 本地文档修订版和章节、脱敏夹具 ID、服务器身份和测试结果。 |
| 传输 | 有文档依据的方法/路径、路径/查询/正文参数、认证引用、超时和取消。不得从 OpenCode 推断路由。 |
| 作用域与 ID | 会话/工作区映射、分页、不透明 ID 的稳定性、远程与本地路径的含义。 |
| 成功与失败 | 响应解析器、状态/错误映射、缺失/null/空值的区别、校验失败和副作用。 |
| 异步行为 | 接受响应、状态/事件来源、终止证据、决策请求、重新连接和未知结果处理。 |
| 支持状态 | `unverified`、`supported`、`adapted` 或 `unsupported`，并附限制和证据；运行时可用性另行记录。 |
| 实现 | 任务包允许修改的生成处理器/编解码器文件，以及夹具和真实运行检查引用。 |

操作所需字段留空会阻止其支持声明。有文档证明操作缺失时，将其标记为 unsupported 并注明来源。如果文档未说明，则标记为 unverified 并记录具体问题。认证错误不能证明功能不存在。

## 从接口文档到适配器的判断

工具包先将提供的 API 文档转换成本地端点清单，再生成实现任务包。每个端点记录保留文档章节、方法、路径、请求/响应定义及副作用分类。OpenAPI 输入可以确定性地填充结构字段。文字文档输入生成附有来源摘录的候选记录；本地维护者核对这些记录后，才能据此授权调用。仅凭示例不能确定错误、分页或完成语义。

将端点清单与冻结的共享操作进行双向核对。每项共享操作都有映射或具体证据缺口。文档列出的每个 CAgent 端点都有共享操作映射、命名空间扩展处理结论，或说明它为何不在当前产品范围内。多个端点可以实现一项操作，一个端点也可以服务多项操作；端点数量不能证明功能覆盖完整。

| 映射结论 | 交给本地 Agent 的工作 | 启用门槛 |
| --- | --- | --- |
| 语义相同，仅方法/路径/字段名称不同 | 填写声明式映射，由工具包生成处理器和常量。 | 请求匹配、响应校验及真实操作验收。 |
| 已确认的语义差异 | 在该任务包内实现一项受限的类型化编解码器，并附文档中的差异及固定示例。 | 负向夹具与真实运行检查证明所需语义得到保留。 |
| 文档明确缺失，或无法满足所需语义 | 记录 unsupported，注明章节和受影响功能 ID。 | 宿主和 UI 拒绝依赖它的功能，不伪造替代成功。 |
| 文档未说明、相互冲突或不完整 | 记录 unverified 和具体问题，保留未完成映射。 | 维护者补充证据后，才能实现或启用该操作。 |
| CAgent 新增能力 | 语义等价时使用共享操作，否则使用固定扩展模板。 | 扩展验收；模板无法表达交互时记录 `requires-host-development`。 |

弱 Agent 不负责选择协议架构、拼造未记载的路由，或修改功能依赖规则来迁就映射。一项任务包停止时，已验收的其他任务包仍然可用。恢复任务时加载其映射、当前生成桩、最小失败夹具及上次结果记录，无需从对话历史重新推导决策。

CA-02 使用示例文档测试这个收集流程，涵盖字段改名、语义差异、文档明确缺失的操作、冲突定义及新增能力。预期处理结论属于受保护的参考数据。工具包必须拒绝猜测路由，或没有验收证据却已启用的能力。这些是示例工具包检查，不代表真实 CAgent API 的结论。

## 按操作拆分的工作顺序

1. 运行未经修改的工具包基线。记录其修订版和检查输出。遇到设置缺陷时停止；不要在适配器任务内修复共享契约或依赖。
2. 绑定一个明确选择的 CAgent 端点和现有秘密引用。完成只读身份/工作区任务包。使用隔离测试工作区，并让普通用户保持适配器禁用。
3. 编辑代码前，依据文档填写相关映射行。生成桩并使用提供的传输辅助工具。夹具请求必须匹配方法、路径、标头、正文和作用域，不能只返回相同响应。
4. 实现一个解析器/操作，并运行固定任务包测试，包括字段缺失和失败场景。如果语义不清导致任务包连续两次失败，停止该任务包，留下最小失败样例和问题；已验收的无关任务包保持不变。
5. 交付最小交互路径：对话绑定/创建、分发、可观察的完成状态，以及受支持时的重新打开/历史。在启用可能要求决策的服务器模式前先加入决策支持。附件、取消等其他功能只通过各自门控加入。
6. 完成其余功能清单。在 UI 关闭时运行能力依赖检查和宿主分发器直测。每项依赖不受支持或尚未验证时，都必须禁用功能并保留已有排队意图。
7. 盘点共享操作列表中缺少的每项 CAgent API 功能。将等价语义映射到共享操作；对受支持的表单/操作/结果交互使用扩展模板；否则记录 `requires-host-development`，并给出具体交互示例。
8. 运行本地真实运行检查和宿主流程。记录适配器/服务器版本以及所有已启用功能的证据。本地维护者审查报告，并明确启用已验收的适配器修订版。保留上一个已验收修订版以便恢复。

生成的任务包包含这些固定字段：操作 ID、目标、文档摘录引用、所需输入/输出语义、允许修改的文件、夹具 ID、准确检查命令、成功标准和停止条件。架构负责人冻结任务包格式；本地 Agent 只填写实现和结果字段。

## 弱 Agent 的任务包执行

受保护的运行器根据已满足的依赖选择下一个任务包。本地 Agent 只接收该任务包的契约页、引用的 API 摘录、允许修改的文件和最小失败样例。名称、导入和注册由运行器生成。Agent 填写有文档依据的映射，或实现一个受限编解码器；尚未解决的语义问题先交给维护者，再继续生成代码。

任务包进度与能力支持、生产启用分开记录：

| 任务包检查点 | 必需证据 | 下一步 |
| --- | --- | --- |
| 映射就绪 | 必填字段引用本地文档，并保留契约语义。 | 生成允许修改的桩和夹具。 |
| 夹具检查通过 | 受保护检查验证请求构造、结果／错误解析和语义失败场景。 | 提交候选实现，进行隔离的真实运行检查。 |
| 真实证据已审阅 | 维护者审查记录修订版上的真实操作结果及依赖功能行为。 | 将操作纳入明确验收的适配器修订版。 |
| 阻塞 | 保存缺失章节、冲突定义或可复现的失败案例。 | 请求具体证据或宿主改动；继续独立任务包。 |

这些是工作流程检查点，不是额外的运行时能力状态。检查点结果由运行器记录；模型自行编写的成功文字不能推进检查点。失败输出包含操作、检查 ID、脱敏的预期／实际差异和一个后续动作。运行器使用固定路径和命令，Agent 不负责选择测试运行器或修复仓库环境。

任务包结果文件保存文档引用、候选文件、检查结果和未解决问题。在新的上下文中依据这些产物恢复。两次修正尝试仍未成功时，将最小剩余失败交给维护者；候选实现保持禁用。仅通过夹具检查不得授权真实变更操作或启用能力。

CA-02 必须在全新的离线上下文中演练该流程：完成一个结构映射任务包，停止一个文档冲突任务包，仅凭已保存产物恢复一个中断任务包。使用执行者／模型时记录其实际身份，并区分脚本运行器测试和模型试验。CA-03 还要记录目标环境内实际本地 Agent 的试验；失败任务包保持禁用，也可由维护者补完，验收检查不得削弱。

## 本地 Agent 提示模板

CA-02 根据维护者核对过的映射和受保护任务包清单，生成以下提示。用已交付工具包中的准确本地引用和命令替换占位符。这是模板，不是可执行工具包，也不是已批准的 CAgent 映射。

```text
在检查点 <任务包 ID> 实现操作 <生成的操作 ID>。
阅读 <一份契约页面> 和 <已批准的 API 章节>。
使用 <生成桩> 和 <宿主传输辅助模块>。
仅修改 <任务包文件白名单>。必需行为：<任务包语义>。
运行 <受保护任务包命令>。通过或失败由运行器判定。
返回候选文件路径和运行器结果引用。
若必需语义缺少证据，返回对应契约字段、
冲突或缺失的 API 章节，以及一个问题。停止本任务包。
若实现检查失败，使用提供的最小失败样例；
耗尽本任务包剩余修正预算后停止。
维护者验收前，候选实现保持禁用。
```

运行器在调用 Agent 前验证每项引用输入。文件缺失、输入超限或映射尚未解决属于准备失败，不消耗模型修正次数。模型回复只能是候选提交或证据缺口记录，不能直接修改任务包状态、能力支持或启用状态。提示采用实际本地模型能够可靠遵循的语言，生成的 ID、路径和命令保持原样。CA-03 记录该语言选择及观察到的指令遵循失败。

## 本地模型工作预算

符号、导入、注册、结构字段映射及测试命令使用确定性生成。本地模型只在构建阶段编写候选适配器。生产分发执行已验收代码，不在运行时要求该模型解读文档、选择端点或动态翻译请求。

工具包提供以下初始任务包限制。维护者可以在测量实际本地模型后调整，并将调整后的限制与工具包修订版一起保存。

| 预算 | 初始限制 | 超限处理 |
| --- | --- | --- |
| 语义范围 | 一项操作，至多一个自定义编解码器 | 按有文档依据的依赖拆分，或返回架构问题。 |
| 可写实现文件 | 至多四个生成文件 | 共享变更交由生成器处理；适配器边界外的修改交由架构负责人处理。 |
| 模型输入 | 至多 8,000 token，包含指令、摘录、代码和失败输出 | 拆分任务包，或由维护者选择必需摘录。不得静默截断必需语义。 |
| 模型输出 | 每次尝试至多 2,000 token | 减少生成桩内尚需完成的工作，或拆分编解码器。 |
| 修正次数 | 初始候选之后至多两次修正尝试 | 保存最小剩余失败，并交回维护者。 |

有可用的离线 tokenizer 时，用工具包提供的 tokenizer 计数。如果缺少该模型的 tokenizer，记录此缺口，并使用维护者认可的、经过测量的输入大小限制；不得将字节或字符数报告为准确 token 数。这些限制约束工作量和成本，不证明语义正确。

运行器区分环境设置失败、API 证据缺失或冲突、实现失败和真实运行验收失败。只有实现失败消耗模型修正次数。设置缺陷交回工具包负责人，证据缺口交回本地维护者。这两种情况都不要求弱模型修复共享基础设施或猜测 API 行为。

CA-02 演练与 CA-03 本地模型试验记录尝试的任务包数、受保护检查通过数、修正次数、维护者介入次数和耗时。记录输入大小及计数方式，并保留每个失败任务包的证据缺口。模型成功率不能替代逐操作启用门槛；报告用于判断提供的工作量是否适合该环境。

## 功能处置与扩展

| 功能 ID | 依赖规则 | 支持结果 | 用户可见结果 | 证据 / 后续负责人 |
| --- | --- | --- | --- | --- |
| 生成的现有 ID | 固定的 all-of/any-of 规则 | 有证据前为 Unverified | 验收前禁用并说明原因 | 本地文档、夹具/真实运行报告 |
| 生成的 CAgent 扩展 ID | 有版本的 schema和已注册处理器 | 有证据前为 Unverified | 验收后才显示扩展面板 | 兼容模板或 requires-host-development |

这些行是模板，并非对真实 CAgent 的发现。报告必须列出所有现有调用方功能，以及所提供 API 文档中找到的所有额外 CAgent 功能。如果文档清单不完整，应说明此限制。不得将未检查的功能标记为不支持，也不得声称已穷尽服务器功能。

扩展记录包含操作 ID、schema 版本、上下文、标签/本地化键、输入/输出类型、效果类别、授权、进度/终止/未知行为、取消、宿主可用性和证据。假设的额外操作只用于测试工具包渲染器；不得暗示 CAgent 确实提供该操作。

## 必需的负向检查

- 不受支持的操作会在任何请求或文件写入发生前被宿主分发器拒绝，包括直接调用方和快捷键。
- 功能虽标记为 supported，却缺少已验收证据、缺失依赖、使用未知schema 版本或未注册扩展处理器时，验证必须失败。
- 错误认证、格式错误的响应和断开的流保留权威状态，不能转化为空成功或永久不支持。
- 已提交请求若丢失确认，结果仍为未知；重试依据已验证的 CAgent 语义，不能依赖时间戳/文本匹配。
- 有待处理工作时切换后端，应拒绝过时结果，也不得向 CAgent 发送 OpenCode 请求、插件、配置写入或排队意图。
- 扩展处理器被直接调用时，其变更操作也不能绕过授权、schema 校验或声明的上下文。
- 修改共享源码、受保护测试或依赖规则时，任务包的变更文件检查必须失败。恢复这些文件后，工具包基线恢复。
- 即使适配器自身报告成功，由维护者掌控的执行器也必须拒绝受保护产物摘要不一致的结果。执行器独立运行检查，不依赖本地 Agent 提供的命令。

## 验收报告与回滚

记录应用/工具包/适配器修订版、服务器身份来源、API 文档修订版、已启用功能列表、不支持列表、未验证列表、原生扩展列表、requires-host-development 列表、测试结果、宿主覆盖范围和维护者决定。夹具专用结果与真实运行结果分开记录。CA-03 要求真实可用的最小聊天路径；若 API 无法提供，应升级已记录的缺口，不能以空能力集通过验收。

报告中要包含一个实际观察到的分发失败/未知案例，以及一次因功能禁用而拒绝直接调用的案例。对每个声称支持的宿主运行检查。未经测试的宿主对 CAgent 保持不可用，并保留其现有 OpenCode 行为。恢复到上一个已验收适配器修订版时，必须保留配置和排队意图，且不得自动跨后端分发。如果不存在已验收修订版，则禁用 CAgent 并返回连接设置流程。
