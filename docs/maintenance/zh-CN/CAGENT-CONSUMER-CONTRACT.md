# CAgent 消费方契约迁移

状态：设计要求，2026-10-09。这是 CA-01 的验收要求，不代表 CAgent 同步源已经实现。请与[架构 SPEC](CAGENT-INTEGRATION-SPEC.md)和[消费方清单](CAGENT-BOUNDARIES.md)一并阅读。英文源文件为[英文版](../CAGENT-CONSUMER-CONTRACT.md)，两者要求相同。

## 为什么现有投影不够

源码检查发现，[UI 模型](../../../packages/ui/src/lib/opencode/model.ts)中包含必需的 OpenCode 信息：会话 `projectID`、绝对路径 `directory`、创建和更新时间，以及 assistant 的 provider/model 字段。[SyncSource](../../../packages/ui/src/sync/source.ts)只接受 OC1/OC2，按消息时间对历史排序，并要求以 OpenCode 为中心的项目、配置和资源清单引导操作。现有线协议标签并不构成 CAgent 协议契约。

宿主的中立 Agent 契约和共享请求客户端只是基础，并未让这些消费方与后端解耦。实际 UI、store、sync 和自主调用方完成迁移前，不要启用宿主功能。仅有成功的宿主处理器或通过的适配器夹具，不足以满足要求。

## 契约归属

CA-02 冻结工具包之前，架构负责人应先修改共享消费方契约及其调用方。环境内 agent 只根据已冻结的契约实现生成映射和范围明确的编解码器。发现不兼容的共享要求时，应提交宿主开发请求，不得因此扩大本地 agent 可编辑的文件范围。

增量迁移期间保留现有 OC1/OC2 投影及回归覆盖。在中立源上明确记录后端家族归属，不要把 CAgent 标成 OC1/OC2。任何独立的 CAgent 展示方式都必须记录功能处置结果，并使用相同的身份、分发和可用性权威来源。独立展示不意味着可以悄悄省略清单中的项目。

## 缺失信息与受影响的消费方

| 信息 | 消费方必须遵守的行为 | 证据门槛 |
| --- | --- | --- |
| Workspace ID 和本地目录 | 保留远端不透明 ID。只有通过明确且已验证的宿主映射，才能绑定本地目录。没有该映射时，禁用依赖路径的 Git、文件和终端操作。 | 两个相互独立的 workspace（包括一个无法访问本地文件系统的 workspace）不能读取或修改彼此的状态。 |
| 项目身份 | CAgent 会话引导时，项目补充信息必须可选。项目 API 缺失不等于已权威确认项目列表为空。 | 即使可选项目补充信息不可用，核心聊天仍能基于已验证的会话/workspace 绑定启动。 |
| 消息/会话时间戳 | 保留缺失的时间戳。显示时间顺序不可用，并省略依赖时间戳的时长或分组。保留文档规定的分页/事件顺序，并使用稳定的本地次级排序键；本地接收时间可单独保存并明确标注。 | 缺失或相同的时间戳、多页数据以及重叠的历史/实时更新都能保留顺序和身份。不得把生成的时间戳报告为服务器时间顺序。 |
| Provider、model、agent 和用量 | 只显示已验证的值。没有模型清单／选择设置操作时禁用模型选择，并省略不可用的费用/token 指标。 | 缺少 provider/model/usage 的消息仍能渲染并重新打开，且不会伪造标识符、声称零费用或更改所选后端。 |
| 工具进度/结果 | 保留有序的各部分，并区分运行中、成功、失败、中断和未知状态。收到消息或流关闭不代表工具已完成。 | 部分输出、错误和丢失的终态证据不得显示为成功完成。 |
| 配置、LSP 和资源清单 | 将可选补充信息与最低引导要求分开。分别报告不支持、未经验证或读取失败的项目。 | 某项补充信息读取失败，不会清除已成功取得的会话/历史数据，也不会隐藏能力不可用的原因。 |
| 决策 | 保留文档规定的选择、范围和待处理状态。问题/表单需要各自已接受的类型化契约。 | 在交付和回复语义都可用前，依赖决策的模式保持禁用；缺少决策 API 不代表获得批准。 |
| 结果观测 | 使用已接受的事件，或采用经过独立测试的状态/历史轮询策略。明确说明轮询成本和延迟。 | 重连和迟到的结果仍绑定当前身份。无法观测到已发起的写操作时，其结果保持未知，不得自动重试提交。 |

派生标签可以使用本地化的“未命名会话”文案。这是展示文本，不代表要更新服务器标题。领域标识符和权威服务器字段必须保留其来源信息。

## 适配任务包规则

每个操作说明页都要区分必需语义与可选补充信息，并列出每个必需字段的消费方。字段映射必须记录以下状态之一：文档记载的值、已验证的转换、文档记载的缺失，或尚无定论的证据。受保护的 runner 会在生成候选代码前验证这份记录。

例如，若文档仅说明会话 ID 和有序消息而没有时间戳，就必须生成不含时间戳的映射，并注明时间顺序方面的限制。不得把 `Date.now()` 写入服务器字段、伪造项目路径、选择默认 OpenCode provider，或为了满足引导流程而返回空资源清单。此处是合成的决策示例，不代表 CAgent API 的实际情况。

基线摘要、检查项、预期处置和任务包依赖项，必须来自 agent 可写文件范围之外、由维护者管理并冻结的工具包。重新计算已修改工作区的摘要不能证明其可信。CA-02 必须分别提供只读权限和独立检查的证据；仅有文件白名单或模型编写的通过报告并不充分。受信任宿主中的适配器执行仍是原生代码执行，不是进程沙箱。

## 验收与顺序

CA-01 根据完整清单记录受影响的调用方，并迁移最低限度的聊天/sync 消费方及所有拒绝路径。测试须覆盖不含 OpenCode 专属补充信息的合成后端、保留的 OC1/OC2 行为、后端切换，以及直接/自主调用的拒绝路径。每项功能都要列出已迁移的消费方；否则须保持不可用并说明原因。

CA-02 打包冻结后的消费方契约、逐字段映射规则和受保护的反例。使用新上下文的演练须覆盖缺失时间戳/provider、本地目录映射缺失，以及试图更改受保护预期的情形。runner 必须按规定处置，不猜测事实，也不允许模型修改测试。

CA-03 验证实际环境的语义和用户操作流程。合成的稀疏后端测试不能证明兼容 CAgent。紧急顺序仍为 INT-00、CA-00、CA-01、CA-02、CA-03，然后才处理其他 INT 里程碑。后续 Legacy 或 UI 里程碑不得绕过 CAgent 优先级门槛。
