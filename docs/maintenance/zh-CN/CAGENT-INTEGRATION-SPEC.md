# CAgent 集成架构

> 中文审阅稿：本译文供审阅使用，英文文档是实现交接的规范版本。

状态：计划中，2026-10-08。CAgent 有独立的 Server API，且只能在目标环境内访问。此处尚未验证任何 CAgent 端点、schema、功能或成功集成。CA-01 实施前，使用已冻结的[调用边界](CAGENT-BOUNDARIES.md)及其完整方法处理注册表。

这项紧急需求优先于[集成里程碑](OPENCODE-INTEGRATION-MILESTONES.md)中的其他实现工作。它扩展[集成规范](OPENCODE-INTEGRATION-SPEC.md)，并取代其中原先排除独立 Agent 服务器的条款。CAgent 是明确命名的第二类后端；通用插件市场和任意协议框架仍不在范围内。[英文原文](../CAGENT-INTEGRATION-SPEC.md)用于实现交接；本中文副本遵循共享的双语审阅规则。

## 交付拆分与归属

[工作流验收契约](CAGENT-WORKFLOW-ACCEPTANCE.md)负责运行时模型质量准入，与适配器支持和适配模型校准分别判断。其门槛适用于无人值守调用者及其使用的 CAgent 独有扩展。CA-03 可以在明确禁用无人值守工作流的情况下，验收可用的交互路径。

两类 Agent 承担不同职责。CAgent 是应用通过 Server API 调用的运行时后端；环境内适配 Agent 是读取文档、编写候选适配器的开发工具。两者可能使用相同模型，但任一职责都不能为另一职责授予权限。适配 Agent 不能批准自己的产出，运行时 CAgent 也不能修改应用的能力注册表。

适配器正确性与 CAgent 任务质量须分别提供验收证据。工具包通过生成代码、小任务包和独立检查减少映射错误及指令遵循错误，但不能提升后端模型的推理准确率。API 调用成功只证明其文档定义的操作语义。启用无人值守流程前，须独立验证该流程所需的决策处理、结果观测和取消能力；本地报告应记录任务质量限制，不能将其当成协议不兼容。

架构负责人先准备可用的适配工具包，再将工作交给环境内的 Agent。本地 Agent 阅读提供的 API 文档，只修改生成的 CAgent 适配器工作区，不重新设计共享 UI、存储、调度、认证或传输。维护者审查所得证据，并授权在该环境中启用。

| 交付项 | 负责人和证据 |
| --- | --- |
| 共享契约与隔离 | 架构负责人提取实际使用的契约，并迁移 SDK 泄漏，同时保留 OC1/OC2 回归覆盖。 |
| 适配工具包 | 架构负责人交付可编译桩、schema、示例适配器、固定测试、离线依赖和简短任务包。刻意不完整的适配器必须无法通过相关检查。 |
| 真实 CAgent 实现 | 本地 Agent 映射有文档依据的操作，提供脱敏夹具，并在允许的工作区内实现受限编解码器和传输钩子。 |
| 验收 | 本地维护者验证真实服务器、已启用功能、已禁用功能和扩展行为。仅靠模拟不能通过 CAgent 验收。 |

工具包是 CA-02 的实现交付物，并非这些规划文档已经生成的内容。其可执行命令和准确文件路径将在 CA-02 中依据实际仓库冻结。[适配器工作手册](CAGENT-ADAPTER-WORKBOOK.md)现阶段定义工具包的输入、输出和本地流程。

## 先跑通最小路径，再扩展覆盖范围

扩展操作覆盖范围前，先实现并演练一条完整路径：有文档依据的身份／工作区绑定、会话绑定或创建、一次分发，以及权威结果观测。使用生产环境计划采用的同一适配器、宿主分发器、能力检查和真实应用消费者。样例后端还必须演示分发失败、结果未知，以及拒绝一项不可用功能。这项试点证明架构能够承载会话；它不能证明真实 CAgent 支持，也不能替代 CA-01／CA-02 的完整验收。

进入目标环境后，维护者先检查文档中的操作能否表达这条路径。如果无法观测完成状态，或无法观测并处理必需的决策请求，保存具体缺失语义并停止启用聊天。只读功能可以单独验收，但不能满足 CA-03 的最小聊天门槛。本地路径跑通后，再扩展可选操作和 CAgent 专属扩展。CA-03 验收前仍须提供完整功能处理报告。

架构负责人提供试点所需的共享 UI 和宿主行为。本地 Agent 只填写有文档依据的映射和受限编解码器。共享消费者或缺少宿主交互造成的试点失败，交回架构负责人处理，不扩大本地 Agent 的编辑范围。

## 后端身份与分发

在现有权威描述符中增加后端家族标识。OpenCode 保留 OC1/OC2 代际及 Auto/OC1/OC2/Legacy 选择。CAgent 有自己的适配器 ID、适配器修订版、契约版本、服务器身份与版本来源，以及能力修订版。CAgent 不需要也不得伪造 OpenCode 代际或配置档字段。后端选择、连接模式和兼容性选择彼此独立。

必须显式选择 CAgent。Auto 仍只解析 OpenCode 配置档；OpenCode 探测失败绝不自动选择 CAgent。只有有文档依据的只读探测才能验证 CAgent 适配器身份。缺少版本信息时仍标记为用户声明/未验证。端点、认证身份、后端家族或适配器发生替换时，旧连接代次失效。能力变化会使受影响的可用性判断失效，并在分发时重新检查。保留原身份下的排队意图，不得在另一个后端重放。

初期仅支持显式配置的外部 CAgent 服务器。只有在启动、就绪和关闭契约有文档说明并经过测试后，才添加托管服务器命令启动。PATH、配置的可执行文件和捆绑的 OpenCode 启动契约在 CAgent 启动器取得同等证据前仍专属于 OpenCode。每种不可用模式都要显示原因；选择 CAgent 绝不安装或启动 OpenCode 作为回退。

## 一份适配器实现，受限接入宿主

在逐步迁移期间保留现有面向调用方的门面。领域契约依据实际调用方定义，不依据 OpenCode SDK 或未知的 CAgent schema 定义。OpenCode 适配器继续使用已验证的 SDK 边界。CAgent 通过运行于可信宿主中的独立、有文档依据的 API 适配器模块接入：Web 后端或 VS Code 扩展宿主。Electron 复用其进程内 Web 后端。两个宿主将相同的 CAgent 编解码器和操作实现与各自现有的传输/认证负责人组合使用。

共享 UI 通过现有运行时契约调用明确的 OpenChamber 操作；自主任务使用同一个宿主操作分发器。CAgent 凭据和协议载荷留在宿主边界。精简的消息/事件桥接暴露规范化结果。明确注册的操作必须先于通用 OpenCode 转发注册；选择 CAgent 时拒绝仅适用于 OpenCode 的代理路径。不得设置独立 sidecar、浏览器端重复的 CAgent 适配器，或假装 CAgent 实现了 OpenCode URL 的代理。

CA-01 冻结具体模块映射和迁移清单。只移动已使用操作所需的协议假设，避免全仓库重命名。现有同步、持久化、队列和原生职责保持不变。最低契约分组如下：

| 分组 | 所需语义 |
| --- | --- |
| 身份与工作区 | 后端身份、认证结果、能力以及远程工作区的含义。不得假定本地路径能标识远程 CAgent 工作区。 |
| 会话与历史 | 不透明且有作用域的 ID、受支持时的创建/列表/读取、分页、消息/部分内容，以及权威读取失败。 |
| 分发与活动 | 输入、受支持时的附件、已接受与已完成的区别、终止错误、可观察活动和取消能力。 |
| 事件与恢复 | 类型化领域更新、稳定实体身份、权威协调和明确的未知结果。经过测试的状态/历史轮询路径可替代缺失的流式能力；须声明其延迟和成本。 |
| 决策 | 按有文档依据的语义交付权限/问题并接收答复。缺少决策 API 绝不表示已授予权限。 |
| 配置与工具 | 分别设门控的目录、设置、凭据、MCP、插件和重新加载。OpenCode 配置文件与插件格式绝不成为 CAgent 默认项。 |
| 扩展 | 按下文扩展契约定义的、带版本的 CAgent 专属类型化操作和结果。 |

不得伪造令牌数、成本、时间戳、完成状态、远程文件系统访问或取消成功。如果无法提供某项必需语义，其依赖功能必须保持禁用。保留不透明的原始 ID，并使用现有运行时/工作区作用域隔离冲突。

[消费契约迁移](CAGENT-CONSUMER-CONTRACT.md)规定共享聊天和同步如何处理缺失的 OpenCode 专属信息。CA-01 必须迁移这些消费者后才能启用宿主支持；只有中立请求客户端还不够。CA-02 将这些规则冻结到本地 Agent 的操作说明和受保护样例中。

## 能力证据与功能可用性

架构负责人根据当前调用方生成完整的“功能到操作”依赖注册表，其中包括浏览器关闭时的调用方。将每项当前功能分类为 OpenChamber 自有、依赖后端或混合型。Git/文件系统操作仅在其实际所属宿主具备所需访问权限时可用；远程 CAgent 工作区本身不代表具备该访问权限。

为每项 CAgent 操作记录 `unverified`、`supported`、`adapted`、`unsupported` 之一，并附证据、限制和原因。文档可确立候选映射或明确缺失。运行时验收只能确立特定适配器/服务器契约的支持情况。对未验证路径发生超时、认证失败或 404 属于连接/契约错误，不能证明该功能永久不受支持。临时可用性须与兼容性支持分开记录。

有效功能可用性取以下条件的交集：操作支持已验证、语义限制已声明、宿主已实现、当前已授权且已就绪。若存在替代实现，须冻结明确的 all-of/any-of 依赖规则。仅在清单中声明 `supported` 不能启用功能；验证器要求关联的验收证据。产生副作用前仍须进行运行时检查。适配器/服务器契约变更后重新验证。

| 调用方 | 缺少前置条件时的必要行为 |
| --- | --- |
| UI 控件、菜单和快捷键 | 在所属 UI 中禁用已有功能并说明有用原因；省略无关设置并展示能力摘要。快捷键和深层链接遵守相同限制。 |
| 队列、计划任务、assist、目标及其他自主调用方 | 拒绝新的不受支持工作；保留已有意图并标记阻塞原因。不得消费、改道或标记为成功。无关工作继续运行。 |
| 核心聊天 | 要求绑定身份/工作区、创建或绑定有文档依据的对话、分发并可靠观察结果。历史、附件、停止和决策各有独立门控。如果服务器可能要求无法回答的决策，则禁用受影响的聊天模式。 |
| 缺少停止能力 | 禁用 Stop，以及依赖取消的无人值守模式。只有在能观察完成状态且 UI 明确说明无法取消时，才可保留用户明确选择的交互模式。关闭视图不代表服务器已取消。 |
| 配置、插件、MCP、OAuth 和重新加载 | 分别禁用每项不受支持的操作。不得写入 OpenCode 配置、注入 OpenCode 插件、迁移存储或对 CAgent 调用 dispose。 |

在目标环境之外无法对任何实际 CAgent 功能分类。本地能力报告必须区分已证实不支持的操作与尚未验证的工作。使用[工作手册的报告字段](CAGENT-ADAPTER-WORKBOOK.md#功能处置与扩展)，逐项记录每个现有功能和文档中的新能力，以及宿主归属和计算得到的可用性。Legacy 承诺保持不变；CAgent 可以交付有明确验收记录的精简功能集。

## CAgent 专属能力

将没有共享等价语义的能力保留在 `cagent` 命名空间下。每项扩展声明稳定的操作 ID、schema 版本、标签/本地化键、上下文要求、输入/输出 schema、效果类别、授权、取消与结果语义，以及证据引用。ID 和字段键来自注册表与实现共享的生成常量模块。

CA-02 提供有限的渲染器：输入支持文本、数字、布尔值、选项和有界列表；结果支持文本、结构化字段和表格。它支持读取操作以及带可见进度和未知结果的显式变更操作。清单只能选择这些固定组件和已注册的适配器处理器；不得包含 JavaScript、HTML、可执行表达式、任意 URL 或 shell 命令。schema 限制、访问检查和副作用声明必须由宿主分发器强制执行，不能只依赖渲染器。

符合共享语义的新操作使用共享契约。符合渲染器能力的 CAgent 专属操作成为命名空间扩展，无需修改共享 UI。需要新交互模型、二进制处理或原生权限的操作记为 `requires-host-development`，保持禁用，并交由架构负责人实现专门的类型化组件/处理器。不得将交互式工作流压平成文本操作而丢失语义。这条路径保留未来支持能力，无需弱能力 Agent 重写核心 UI。

每项已交付扩展都要测试输入拒绝、效果/权限检查、成功结果解析、失败/未知结果、后端切换和不可用宿主。未知扩展schema 版本保持禁用。扩展可用性绑定到与核心操作相同的后端身份和能力修订版。

## 本地 Agent 限制与验证

工具包会在可写适配器工作区之外冻结共享契约、参考测试、功能依赖规则和扩展 schema。每个任务包只安排一项操作，并附相关文档摘录、输入/输出示例、允许修改的文件、固定测试命令和完成规则。应生成操作桩和注册表，不要让模型自行发明架构或符号。文档有歧义时应记录具体证据缺口，不得猜测映射。

简单的方法/路径/字段采用确定性映射。经验证的语义差异由自定义类型化编解码器处理。两者都须通过相同夹具和宿主级检查。映射文件和导出报告中不得包含秘密；运行时认证使用现有秘密管理方。工具包使用经过测试的工具链和依赖离线工作；环境内无需安装软件包或联网生成代码。

本地执行器通过文件系统权限落实编辑边界，共享契约和参考测试保持只读。提示词中的文件白名单不构成强制约束。验收任务包前，由维护者掌控的执行器将受保护产物的摘要与冻结工具包比对，并运行自身的检查。适配器代码、模型编写的报告和适配器提供的测试命令均不能重新定义这些检查。CA-02 必须证明受保护产物被改动以及越界修改源码时，验证都会拒绝通过。

架构负责人提供负向夹具和基线测试；本地 Agent 不得通过修改它们满足验收。变更文件白名单检查、schema 验证、夹具重放和功能覆盖检查会拒绝任务包范围之外的改动，或拒绝启用不受支持的能力。仅有本地夹具不足以验收：本地维护者须对隔离的服务器工作区运行真实流程，并签署证据报告。这些控制可降低模型错误，但不能让其自报测试结果变得可信。

分发歧义和目录释放遵循[共享集成契约](OPENCODE-INTEGRATION-SPEC.md)与 [Legacy 分发契约](OPENCODE-LEGACY-1.2.27-SPEC.md)中的证据标准。CAgent 必须独立证明任何幂等性、结果查询或目录释放语义。Legacy 证据不能证明 CAgent 受支持。

工作手册中的[本地模型工作预算](CAGENT-ADAPTER-WORKBOOK.md#本地模型工作预算)限制任务包范围、上下文、生成文件及修正次数。工具包生成机械代码，将模型编写工作限定在有文档依据的语义差异。生产环境使用已验收的适配器代码，不依赖弱本地模型进行请求路由或协议转换。CA-02 和 CA-03 除验收结果外，还记录实际执行成本和维护者介入情况。

分配真实 API 任务包前，先校准实际编写适配代码的模型。工作手册中的[校准与任务分配](CAGENT-ADAPTER-WORKBOOK.md#本地模型校准与任务分配)决定它填写声明式映射、尝试局部编解码器，还是采用维护者独立完成的路径。模型限制改变任务分配；各条路径保持相同的操作验收与启用门槛。原始 API 文档和模型对话保留在目标环境内部。

## 宿主验收与优先级

| 宿主 | CAgent 执行与验收 |
| --- | --- |
| Web | 后端适配器加认证后的共享操作路由；浏览器关闭时的任务与 UI 使用相同能力。 |
| Electron | 相同的进程内后端；渲染器/主进程副本中不含 CAgent 凭据或协议实现。验证桌面端切换和退出职责。 |
| VS Code | 扩展宿主中的相同适配器，使用现有专用消息/事件桥接。在测试前，明确标记 CAgent 宿主选项不可用。 |
| Hosted mobile | 使用所选服务器的适配器和能力摘要；验证触控扩展表单及重新连接。 |
| Capacitor | 使用所选 OpenChamber 宿主；不运行本地 CAgent 进程。真实连接流程通过前，不支持的宿主保持禁用。 |

CA-00 冻结已使用操作和文件归属映射。CA-01 实现宿主契约和能力门控，并通过当前 OC1/OC2 回归。CA-02 使用刻意精简的示例后端和带一个合成额外功能的后端交付并测试完整离线工具包；两者都不得宣称为 CAgent。CA-03 执行环境内适配与真实验收，为每项已使用功能和每项新发现的 CAgent 功能提供能力报告。

只有通用基线工作 INT-00 排在这条紧急序列之前。其余 INT 实现开始前，CA-03 验收是优先级门槛。如果无法访问环境/文档，应报告该门槛被阻塞并交付已完成的工具包；不得悄悄开始优先级较低的工作。维护者可以明确调整该顺序。最终集成仍须通过所有 Legacy 和 OC1/OC2 门槛。
