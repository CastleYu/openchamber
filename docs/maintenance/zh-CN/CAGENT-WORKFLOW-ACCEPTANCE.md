# CAgent 工作流验收

状态：需求，2026-10-09。尚未评估真实 CAgent 模型或工作流。本文负责[CAgent 架构](CAGENT-INTEGRATION-SPEC.md)中的任务质量准入；[适配工作手册](CAGENT-ADAPTER-WORKBOOK.md)负责编写适配器的模型校准及协议适配。[英文交接源](../CAGENT-WORKFLOW-ACCEPTANCE.md)。

## 两项独立判断

适配器验收证明有文档依据的请求、归一化结果和操作语义，不证明后端模型能够遵循指令或正确完成工作。环境内适配模型的校准结果，也不能证明运行时 CAgent 模型的质量。

操作支持状态与工作流准入分别记录。已验收操作可以供交互使用，同时保持依赖该操作的无人值守工作流不可用。工作流质量失败不能把 API 操作重新标为 `unsupported`。能力摘要保留实际原因，负责调用的宿主在派发前执行工作流准入检查。

## 准入记录

架构负责人从当前无人值守调用者中定义有限的工作流 ID。环境内维护者提供并审查证据，适配 Agent 不能批准证据。记录保存在适配器可写工作区之外。

| 字段 | 必需含义 |
| --- | --- |
| 工作流与调用者 | 稳定工作流 ID，以及受其约束的全部 UI、直接调用和浏览器关闭后的调用者。 |
| 范围 | 已验收适配器版本、服务器契约、工作区策略、运行时模型／配置来源和工作流指令版本。明确记录未知来源。 |
| 协议前提 | 现有依赖注册表中的操作支持、授权、就绪、可观测结果、必需决策和取消能力。 |
| 质量证据 | 本地冻结的任务 ID、预期可观测结果、实际结果、指令违反情况和维护者介入记录。 |
| 准入结论 | `unverified`、`interactive-only` 或 `unattended-approved`，附原因及批准维护者。交互可用仍须通过最小聊天及操作门槛。 |
| 变更处理 | 哪些事实变化使结论失效，以及如何保留在途请求的未知结果。 |

这是工作流记录，不能由适配器声明能力代替。实施时在负责的宿主内加入具名常量和类型契约。宿主依据该记录与现有能力检查计算工作流实际可用性。质量批准不能覆盖缺失的协议前提。

## 本地验收步骤

1. 维护者在运行实际模型前，针对具体工作流冻结一组小而有代表性的任务。包括正常任务、需要澄清的歧义输入、信息缺失，以及与该工作流相关的失败或中断。每项任务定义预期可观测结果和允许产生的效果。
2. 使用实际应用调用者及已验收适配器，在隔离工作区运行。记录错误结果、忽略指令、意外效果、决策失败，以及任何人工介入。原始文档和模型输出留在环境内，只导出脱敏的结果引用。
3. 逐工作流审查。平均分或成功 HTTP 响应不能豁免必需用例失败。全部必需用例和协议前提在无人工介入时通过，才可批准无人值守执行。否则该工作流保持无人值守不可用，同时保留已独立验收的交互／只读功能。
4. 运行时模型／配置、工作流指令或相关服务器契约变化后重新核查。无法确认已验收范围时，暂停无人值守准入。保留队列意图及请求未知结果，不自动向另一模型或后端重放。

测试只描述已记录范围，不能保证任意未来回答。准入后仍执行现有的效果边界、授权和结果检查。本需求不新增模型路由器、自动提示词优化器或备用模型。

## 功能报告与扩展影响

功能处理报告将依赖后端的无人值守功能链接到工作流准入记录。禁用原因分别指出 API 语义缺失、宿主实现不完整，或任务质量证据不足。UI 与直接调用使用相同原因。

CAgent 新操作继续遵循有限的类型化扩展契约。API 校验和真实验收证明该操作的行为；无人值守工作流使用它时，还需通过任务质量准入。需要宿主开发的新交互，在对应宿主实现通过验收前保持禁用。

## 里程碑证据

CA-01 在相关宿主调用者中实现准入检查，使用模拟质量拒绝验证直接调用会被拒绝。CA-02 提供协议成功与工作流失败彼此独立的受保护示例；示例不能批准真实工作流。CA-03 记录真实工作流处理结论及本地维护者决定。可用的交互式 CAgent 路径可以在明确禁用无人值守功能的情况下完成 CA-03；无需批准全部无人值守功能。
