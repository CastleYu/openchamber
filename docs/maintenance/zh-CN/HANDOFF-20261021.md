## 扩展前需要处理的审计发现

1. `BackendGate.tsx` 选择 CAgent 后替换原应用，进入 `CAgentApp.tsx`。
   用户需要填写工作区／会话 ID，历史、输入、状态各自实现。这只是有限试点。
   持续扩充会成为第二套前端，偏离复用原项目的目标。
2. `AgentClient.selection()` 要求普通 OpenCode 启动先成功请求
   `/api/agent-backend/selection`，失败就阻断入口。
   对缺少该接口的宿主应作明确兼容决策，不能靠猜测后端身份。
3. `legacy-credential-operations.js` 对远程认证 API 也要求 Windows／原生进程。
   应复核 API 能力与本地配置文件归属的边界，保留身份绑定和权限检查。
4. `message-queue/runtime.js` 停止发送缺少连接标识的旧记录，仍可取回编辑。
   这影响全部模式，需要明确迁移和用户行为验收。
5. Legacy Provider 独立页面重复承担部分通用设置／认证交互。
   应先确认协议差异再复用展示逻辑，不能仅凭文件数量删除生命周期保护。

上一轮静态审计统计，相对个人分支起点，packages 中已跟踪差异涉及 394 文件，
实现约新增 11,199 行，测试约新增 19,705 行，另有未跟踪文件。
