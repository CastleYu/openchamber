## 版本边界

这组能力计划使用 DIJIANG 5.x，衔接当前 4.0 基线。以下子版本是同一个 Agent 集成里程碑内的交付节点，遵循 [BUILD.md](../BUILD.md) 中由维护者划定的功能范围。规划阶段不修改 `featureVersion`、包版本、标签或发布策略。上游包版本独立维护。

内部里程碑验收和公开发布分别决定。早期子版本只能开放已经完成的范围。Legacy 在后续门槛通过前保持实验状态，尚未验证的操作禁用。不能把早期节点发布为完整兼容 1.2.27。拟议的 5.0–5.13 发布编号不规定实施顺序，实施仅遵循声明的依赖。INT-00 是首个可开始的基线。CA-00 至 CA-03 是紧急 CAgent 路径。除 INT-00 通用基线外，其余 INT 实施都要等 CA-03 验收通过。如果无法进入本地 CAgent 环境或取得 API 文档，CA-03 保持阻塞，除非维护者明确调整优先级。若交付顺序或其他任务改变编号分配，在公开发布前统一调整；稳定任务编号继续用于追踪。

本文维护本次集成里程碑的状态和验收条件。PLAN.md 将 RUN-01/RUN-02 引导到这里，不重复维护状态表。原有上游引入和双内核台账保留其历史证据。

## 完成契约

### INT-00：证据与范围

固定实施工作树 SHA，并与此次核查基线比较。并发进行的上游引入应单独记录为建议范围，不能在节点执行中移动目标。核对遗留的失败／未运行测试，判断哪些影响本次范围。历史测试报告不等于干净基线。

将现有接口台账扩展为当前实际使用的操作清单，并对应 Legacy 分组 L01-L15。设计转换前先检查现有模式设置、持久化数据及 OC1/OC2 契约。按照 SPEC 3.1，将现存 SDK/HTTP/SSE 泄漏逐项对应到负责人及明确的迁移或保留决定。

通过条件：每项原始 3.X 需求及新增 Legacy 分组都对应负责人、当前证据、里程碑和验收检查。影响所选工作的当前运行时验证缺口已经解决，或明确阻塞对应工作。精确 Legacy 证据不是本节点的通过要求。

### CA-00：CAgent 操作盘点与边界冻结

在 INT-00 之后，盘点所有已使用操作，包括关闭浏览器后运行的调用者，并将当前功能分类为 OpenChamber 自有、依赖后端或混合功能。冻结 CAgent 的具体模块图、待迁移的协议假设、共享 UI／运行时／宿主归属及受保护文件范围。未知的 CAgent 信息继续标为未知，不假设任何端点、schema、功能或支持状态。

通过条件：每个已使用操作及调用者都对应契约负责人、当前证据、迁移决定和后续验收门槛。生成的清单覆盖直接调用与自主任务调用，并列明受保护的共享文件。实施不得基于猜测的 CAgent API 启动。

已接受的源码分类：[调用边界](CAGENT-BOUNDARIES.md)与[处理注册表](../evidence/2026-10-09-cagent-boundaries.json)。覆盖检查确认恰好分配了 118 项 UI 方法、23 项宿主操作及全部 496 处已记录引用，没有遗漏、多余或重复方法。这是迁移范围验收；可执行守卫和真实后端支持仍属于后续门槛。

### CA-01：类型化宿主契约与守卫

依据实际消费者定义领域契约，只迁移这些消费者需要的协议假设。将一个运行时中立的 CAgent 适配器放在可信的 Web 后端或 VS Code 扩展宿主；Electron 复用进程内后端。在分派时检查权威后端身份和能力，并在产生副作用前明确拒绝不支持的操作。保留 OpenCode 行为并运行 OC1/OC2 回归。

通过条件：类型化宿主操作契约覆盖 CA-00 清单；守卫同时作用于 UI、直接调用者和自主调用者；身份变化会使旧工作失效，且不会跨后端重放。针对性 OC1/OC2 回归通过。没有本地运行时证据时不得宣称支持 CAgent。

### CA-02：可运行的离线适配工具包

交付完整可运行的任务包工具链，不能只交规划文档。包含受保护的参考测试和样本、生成的操作桩／常量、确定性生成器、schema、离线依赖和命令、修改文件白名单校验、功能覆盖检查，以及任务包／报告生成。用刻意精简的样例后端和独立的合成扩展功能样例验证工具包；两者都不代表真实 CAgent 行为。

通过条件：干净的离线工作区能运行文档中的命令。精简适配器正确拒绝不支持的操作，并在错误启用依赖功能时使校验失败；合成扩展只能通过已注册的类型化处理器通过检查。修改受保护测试／契约，或在没有关联证据时启用功能，都必须使校验失败。必要检查失败时返回非零状态和精简机器可读结果。

文档收集流程还要通过[工作手册中的判断用例](CAGENT-ADAPTER-WORKBOOK.md#从接口文档到适配器的判断)。受保护的预期结论覆盖结构映射、语义差异、功能缺失、冲突证据及新增能力。仅有端点清单不能满足功能覆盖要求。

还要通过[弱 Agent 任务包流程](CAGENT-ADAPTER-WORKBOOK.md#弱-agent-的任务包执行)的全新上下文完成、遇冲突停止及中断恢复演练。脚本检查与模型试验分别记录；模型自行报告成功不能推进验收。

CA-02 冻结[本地模型工作预算](CAGENT-ADAPTER-WORKBOOK.md#本地模型工作预算)，演示必需输入超限时如何拆分任务包，并记录演练的执行成本。生产操作分发使用已验收代码，不依赖模型进行路由或转换。

CA-02 还要交付[模型校准样例](CAGENT-ADAPTER-WORKBOOK.md#本地模型校准与任务分配)，演示所有任务分配结果，包括可用的维护者独立完成路径。CA-03 在实现真实 API 映射前，使用实际本地模型运行这些样例，并记录选定工作范围。校准不能替代操作或功能验收。

### CA-03：本地 CAgent 适配与真实验收

在目标环境中使用实际 API 文档和隔离的 CAgent 服务器运行工具包。实现最小可用对话路径，并为所有现有已使用功能，以及 API 文档中发现的额外功能，给出处理结论。未验证或不支持的功能都要附原因并保持禁用；固定扩展模型无法保留语义时记录 `requires-host-development`。维护者只显式启用已验收的适配器版本。

通过条件：本地真实服务器可完成最小对话，并能观察结果；若支持历史和重开，也需覆盖这些流程。每个声明可用的宿主都通过真实连接流程。证据报告完整记录现有及新发现的功能，包括不支持和未验证项，并包含对禁用功能的直接调用拒绝测试。本地维护者审查证据并显式启用该版本。如果无法访问环境或文档，CA-03 保持阻塞，且不得开始低优先级 INT 实施，除非维护者明确调整优先级。模拟不能通过此门槛。

使用工作手册任务包，记录目标环境内实际本地 Agent 的适配试验。失败任务包保持禁用，报告其证据缺口；维护者补完时仍使用相同验收检查。

本地模型试验按工作手册预算记录工作量、受保护检查结果、修正次数、维护者介入次数和耗时。无论整体试验成功率如何，失败或尚未检查的操作都保持禁用。

### INT-00L：精确 Legacy 证据

取得精确 1.2.27 源码／schema 和隔离的可执行程序／端点，记录来源与脱敏样本。确定身份探测、实际使用的协议契约和 dispose 范围。调查幂等键支持、保留期及请求 ID 结果查询，不预设任何能力存在。区分缺少证据和已经确认不支持的行为。

通过条件：证据足以实施首个 Legacy 对话，并明确其他操作各自的门槛。任何未解决的契约在取得证据前保持禁用。若无法运行精确 1.2.27，Legacy 真实运行门槛保持阻塞。在 CA-03 已验收的前提下，INT-01/INT-02 的当前运行时工作、INT-06 及独立 UI 工作无需等待 Legacy 实测。

### INT-01：身份和适配器边界

负责共享描述符／兼容配置／常量、服务器／扩展组合、UI 分派和直接调用清单。在不改变当前 OC1/OC2 含义的前提下加入 Auto 和手动选择。在启动加载或写入前绑定兼容配置与能力。尚无通过验收实现的 Legacy 操作明确失败。

通过条件：选择策略、用户声明的未知版本处理、矛盾版本拒绝、不支持／认证／不可达区分及同 URL 兼容配置切换均通过契约测试。真实身份探测验证当前 OC1/OC2；精确 Legacy Auto／手动选择的真实验收在 INT-00L 后由 INT-03 完成。Web／VS Code 描述符与服务器任务一致；旧兼容配置的迟到结果不能修改新状态。现有 OC1/OC2 核心行为保持可用。审查 SPEC 3.1 消费者契约及修改模块清单，证明新增适配器不需要修改协议无关的聊天／队列业务。

### INT-02：模式与迁移

负责设置记录、配置界面、服务器生命周期和 VS Code 管理器。按 SPEC 实现五种模式，各宿主明确不支持的模式，展示设置来源，不隐式回退到其他二进制或端点。导入设置仅预填待确认候选；缺少选择时只推荐捆绑内核，不直接启动。CLI 写入使用同一认证设置契约，不设隐式覆盖或 UI 锁定。保持单个自有服务器，并显示忙碌工作期间切换的后果。

通过条件：测试各可用模式的有效及无效输入、PATH 缺失、无效 shim／命令、端口占用、缺少捆绑程序、外部认证失败、启动超时、取消、重复切换、重启持久化和旧设置迁移。真实 Windows 运行证明子进程隐藏、自有进程树关闭且不终止外部进程。内核失败后仍可访问配置界面。保存／迁移失败保留先前记录。

### INT-03：首个可用 Legacy 对话

负责 Legacy 请求／响应／错误编解码和 UI／服务器会话操作。覆盖 L01-L03，以及完成对话所需的最小 L06/L09/L10 事件、权限／问题和终态路径。纳入 L07/L13 中必要的提供商／模型等目录读取及预配置凭据使用。使用明确配置的既有托管／外部路径；新五模式 UI 的交付不是前提。其他能力通过验收前保持禁用。

通过条件：真实精确 1.2.27 的 Auto／手动选择、会话创建、文本／附件提交、工具流式输出、权限／问题回复、停止、完成及重新打开历史端到端可用，并与脱敏样本一致。服务器后端和 UI 使用相同兼容配置。新版 OC1 和受支持的 OC2 通过针对性核心回归。高级操作、配置和宿主门槛完成前，Legacy 保持实验状态。

### INT-04：Legacy 高级操作与恢复

负责 L04/L05 命令／shell、fork／compact／diff／revert 及支持的文件／todo 操作，以及其余 L06/L09/L10 恢复工作。在 INT-03 已可用的流与决策路径上扩展缺少回放时的限定范围恢复。在历史／流更新之间保留消息身份，并区分缺失与空值。

通过条件：真实 1.2.27 命令／shell、fork／compact／diff／revert 及受支持的文件／todo 流程符合各自操作台账。工具／权限／问题流程、中断、重连、服务器重启和待决事项恢复完成，不重复消息、不丢失审批。迟到／乱序／不完整事件及恢复失败均有契约测试。局部失败时两个目录仍相互独立。

### INT-05：Legacy 设置与自主任务

负责 L07、L08、L11、L13 和 L15 中的能力核查。配置／提供商／认证／MCP／skills／生成插件和所有无人值守调用者均经过兼容配置分派。验证旧版本的元数据持久化，不假定现代 SDK 字段会被保存。仅较新内核原生支持的功能在服务层给出明确能力结果。

通过条件：精确版本支持的设置读取／写入、凭据处理、插件加载和 MCP 生命周期通过验证；依赖重载的配置应用在 INT-06L 验收。关闭 UI 后，队列、计划任务、assist 和 goals 完成预期分派／状态变化。按 Legacy 派发结果契约覆盖正常单次派发、确认响应丢失、崩溃／重启和重复触发。结果未知时保留意图，没有已验证的去重或可靠结果查询时不自动重发。OC2 迁移、凭据 schema 或仅适配现代版本的插件不能作用于 Legacy 存储。每项已使用的高级操作都有证据支持的处理结论；缺少核心行为时不能通过验收。

### INT-06：当前 OC1/OC2 重载契约

负责当前 OC1/OC2 的原始 3.3，以及 L12 所需的共享范围契约。仅在协议及范围行为已验证后实现目录／全局 dispose。目录重载只推进该目录的生命周期，保留无关请求、审批和订阅；更大范围的连接变化使用连接 epoch。在适当情况下保留 OC2 即时应用和原生托管重启；启动参数／二进制变更使用单独显示的进程重启操作。

通过条件：当前 OC1 和受支持 OC2 上的真实重载证明所需配置生效、受影响的流重新绑定，而且只在成功后清除待应用状态。重载目录 A 时，目录 B 存在活动任务和审批：B 应保持可用且不丢失状态。外部 PID 继续存在。忙碌工作、不支持目录范围、响应丢失、超时和就绪失败均有明确且经过测试的结果。不能把全局释放或进程重启用作未告知用户的回退。精确 Legacy 证据／配置工作不阻塞本节点。

### INT-06L：Legacy 重载与配置应用

使用已验收的共享范围契约和 Legacy 配置适配器，在精确 1.2.27 上完成 L12。不能从现代端点名称推断目录语义。

通过条件：精确版本真实重载应用所需设置、重新绑定受影响的流，并在验证成功后才清除待应用变更。在 Legacy 上重复 INT-06 的隔离性、外部 PID 及失败用例。仅支持全局的能力应显示为明确的全局操作；此时目录重载不受支持，不能隐式扩大范围。

### INT-07：原生本地化

负责 Electron 原生应用／托盘／上下文菜单资源及语言传播。菜单动作和快捷键保留现有归属。

通过条件：截图记录 Windows 中英文菜单随语言切换变化，并执行相同动作；macOS role 菜单和 Linux 托盘行为须有对应宿主验收，或明确保持未完成。共享 UI 本地化不能替代原生验证。

### INT-08：分支上下文与刷新

负责标题分支展示、草稿刷新操作和限定范围的 Git store 刷新语义。两项需求都使用当前会话／草稿目录，与选定的 OpenCode 协议独立。

通过条件：桌面／移动端在工作面板打开时显示分支；Git／非 Git／空仓库／detached／错误情况正确。在应用外切换分支后显式刷新，立即更新当前检出状态，保留有效的用户目标选择和草稿内容，拒绝过期目标结果。刷新失败标记数据陈旧，但目标仍有效时允许发送且不增加确认；仅目标失效／无法解析时阻止发送，目标切换期间可以暂挂。采集真实截图，并验证刷新后依赖目标的发送操作。

### INT-09：快捷键提示

负责通用提示工具／组件和有限的已注册操作覆盖清单。分支刷新只有在确有绑定时才纳入快捷键提示。

通过条件：清单中每个按钮都在悬停／聚焦时显示实际生效的自定义绑定，遵循平台格式，重新绑定后更新，不显示不存在的绑定。提示和实际分派的动作一致。触摸标签与键盘可访问性保持可用。

### INT-10：集成与候选发布版

负责最终集成审查和 L14 宿主矩阵。固定最终 SHA，运行必要的根级检查和受影响构建／测试，再在承诺支持的宿主上验证真实用户流程。核对每项不支持／未验证操作及影响本次里程碑的历史验证缺口。测试 CAgent 契约回归和后端切换，并测试 Legacy／当前 OC1／OC2 切换、设置持久化及先前记录恢复。

通过条件：所有适用的 SPEC 和 Legacy 验收行都有最终 SHA 对应证据。实际运行精确稳定版 1.2.27，不能用新版 OC1 替代。Windows 便携版启动／对话／重载／退出成功，并说明原生宿主限制。在要求准备发布时，设置中的更新历史和发布身份准确描述已验收范围。发布、标签和安装与本次规划任务分开。

## 证据与交接格式

每个 INT 任务记录状态、负责人、基线／最终 SHA、需求编号、修改模块、精确内核版本、样本／测试、真实运行检查、未解决的宿主行及恢复步骤。标记 `done` 需要满足完成契约，仅类型检查通过不够。源码审查、样本测试与真实运行结果分别记录。

使用较短的实施会话，并划分互不重叠的文件归属。主负责人负责描述符和操作契约、共享设置 schema、集成决策及最终审查。后续会话从前一份已验收交接记录开始；新发现的范围进入队列，不合并进不断变化的当前节点。
