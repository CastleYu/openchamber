## 现有架构与目标模型

当前产品已有 `opencodeClient`、UI `v1/` 和 `v2/` 操作、服务端 `kernel-operations.js`、运行时描述符、按代际划分的配置/认证/插件归属方，以及运行时 epoch 检查。OC1 使用 SDK 命名空间 `@opencode-ai/sdk/v2`；这个名称不代表 OpenCode 2.x。OC2 使用 `@opencode/client`。

后端身份与 OpenCode 专属兼容性决策保持独立：

| 决策 | 值 | 归属方 |
| --- | --- | --- |
| 后端类型 | OpenCode 或 CAgent | 持久化的显式选择及经过验证的宿主描述符 |
| 连接模式 | 外部服务器、托管服务器命令、系统 PATH、已配置可执行文件、捆绑可执行文件 | 服务端或 VS Code 扩展生命周期归属方 |
| 协议代际 | OC1 或 OC2 | 已解析的端点描述符 |
| 兼容性选择 | Auto、OC1、OC2、Legacy 1.2.27 | 持久化端点配置；已解析配置是权威值 |

Legacy 是 OC1 兼容配置，不是第三种协议代际，也不是第二个应用。服务端/扩展必须在 bootstrap、自主请求、配置写入或插件物化之前解析配置。即使用户选择 OC1，只要端点报告的版本精确为 1.2.27，仍必须使用 Legacy 配置。配置选择规则由 Legacy 规范负责。

代际／兼容性选择两行仅适用于 OpenCode。CAgent 使用自己的版本化适配器契约，初始采用外部服务器连接。其可用性及启动限制由 CAgent SPEC 负责。不得给 CAgent 指定 OC1/OC2 代际或 Legacy 选择。

扩展现有描述符，加入已选/已解析配置、版本来源、连接模式、连接身份和能力集。身份版本覆盖端点、认证身份、代际、配置和托管运行时替换。任一项变化都应使旧操作失效，并通过现有运行时切换流程重新连接。使用同一后端的客户端和窗口都接收其权威描述符；一个窗口不得悄悄替同伴更改后端。

在所属共享边界中定义具名常量和判别式契约，并按连接模式、配置、生命周期状态和操作分组。不得在 UI、web 和 VS Code 中重复定义模式字符串，也不得引入第二个描述符注册表。凭据继续由既有机密数据归属方管理；公开描述符不得包含机密材料。

## 3.1 适配器补全

保留 `packages/ui/src/lib/opencode/client.ts` 作为面向调用方的服务。配置专属请求、响应/错误解析、事件解码和能力判断属于该边界之下。协议无关的聊天组件和队列业务逻辑留在边界之外。新增协议只需修改适配器、组合点，以及确有协议专属编辑需求时显式归属协议的编辑器。不得构建通用 SDK 或插件框架。

CA-01 先提取消费者使用的领域契约，并处理 CAgent 接入所需的现存 SDK 泄漏。按 CAgent 架构，其实现只在可信宿主适配器中执行，共享 UI 通过明确的运行时操作访问它。现有 OpenCode SDK 路径保留在各自适配器后方。后续环境内 CAgent 适配只修改生成的适配器工作区，不修改这些共享消费者。

端到端验收覆盖消费者的最小操作契约：身份与能力、会话历史、发送与停止、消息事件、权限请求和配置能力。针对每个已解析配置验证支持与不支持的行为，包括读取失败后保留权威状态。不支持的操作必须在派发前拒绝，并说明所选配置和可执行的下一步。

盘点现有直接 SDK/HTTP/SSE 调用出口、动态拼接路由、生成的插件调用和宿主桥接。逐项记录归属方、消费者、配置处置、迁移决定和测试。消费者需要配置契约时迁移调用出口；只有在记录其边界并有证据证明不会绕过配置分派时才保留。新代码不得增加未登记的调用出口。历史 43 行接口表只是起始索引；还要纳入当前 upstream intake 新增的操作。

服务端任务、代理路由、配置/认证处理程序和插件通过各自现有归属方使用同一解析身份。关闭浏览器不得改变队列、计划任务、assist、goals、routing、通知或其他自主调用方所用的配置。Electron 负责原生进程集成；进程内 web 后端负责协议行为。VS Code 使用其扩展端和专用消息/SSE 桥接。

操作必须返回有类型的成功结果，或明确的不支持/错误结果。不得仅因 OC2 原语不同就移除现有 OC1 用户功能。不得把 SDK 联合类型或原始 wire payload 变成新的组件契约。

## 3.2 显式连接模式

以下五种启动契约描述 OpenCode。先选择后端类型；CAgent 初始只启用经过验证的外部服务器路径，其他模式遵循其单独的启动器取证门槛。

连接设置应显示模式、服务器上的目标路径/网络地址、请求的兼容配置、解析出的版本/配置、配置来源、就绪状态和最近一次失败。OpenChamber 宿主选择和 OpenCode 端点选择是不同控件。编辑表单不会更改当前活动运行时。“测试连接”是只读操作；启动命令是显式操作。

| 模式 | 输入和解析 | 归属与失败处理 |
| --- | --- | --- |
| 外部服务器 | 明确的 HTTP(S) 端点，包括主机、端口和可选 base path；凭据由宿主管理 | 只连接到此端点。绝不启动、升级、杀死或接管其 PID。验证失败仍是连接失败。 |
| 托管服务器命令 | 可执行文件、参数列表、服务端 cwd 和明确指定的环境引用；解析其公布的端点，然后探测 | 每个后端连接对应一个受本方管理的进程树。未公布/格式错误的端点、服务器不兼容或超时均使本次尝试失败。仅有输出不代表就绪。 |
| 系统 PATH | 只从后端宿主机生效的 PATH 解析 `opencode`；显示解析出的可执行文件 | 使用原生 OpenCode 启动契约。未找到可执行文件时直接失败，不探测已知安装位置，也不使用捆绑版本。 |
| 已配置可执行文件 | 明确指定后端可执行文件，或受支持的 Windows shim，并传入原生启动契约支持的参数 | 只验证并启动该目标。路径、shim 或参数无效时作为错误处理。 |
| 捆绑可执行文件 | 选择宿主已打包且经过验证的 OpenCode 二进制文件 | 仅当该宿主确实附带捆绑文件时可用。文件缺失/损坏则失败，不下载也不改用 PATH。 |

两种命令类模式的启动契约不同：托管服务器命令使用已配置的服务器调用及其公布的端点；已配置可执行文件使用原生 OpenCode 启动器和受控的 serve 参数。Windows `.cmd` shim 由现有 launch-spec 归属方解析。可执行文件字段不代表任意 shell 管道。后台子进程保持隐藏，其进程归属记录一直保留到确认退出。

模式不代表协议代际。每种可用模式都可以使用 OC1、OC2，或在实际二进制/端点匹配时使用 Legacy 配置。现代捆绑二进制不能通过选择配置变成 1.2.27。

### 已保存设置与迁移

后端存储带版本的连接记录。首次升级时，有效的现有设置和环境变量只用于预填候选值。界面显示每项候选的来源和解析值，并要求用户确认后才能启用。无效或冲突的输入会停止在可见的设置错误状态。没有保存选择时，可以推荐捆绑可执行文件，但不得自动启动。不得扫描端口并接管无关服务器。

已保存记录是启动的唯一权威来源。旧环境变量只用于预填，不得反复覆盖，也不得形成回退链。CLI 可以通过与 UI 相同的认证保存契约显式保存或更新选择，但不得在启动时隐式覆盖该记录，也不得将 UI 设为只读。部署管理员锁定模式不在本里程碑范围内。即使 OpenCode 服务/kernel 失败，OpenChamber 设置服务在设置/失败状态下仍须可访问。

写入迁移记录时保留可恢复的旧连接设置副本。验证或持久化失败时，旧保存记录保持不变。清除设置后回到设置状态，不得悄悄重新发现模式。不得假设旧二进制理解新记录；回滚应使用保留的旧记录。

### 切换、重试和进程生命周期

由一个归属方管理 `unconfigured`、`validating`、`starting`、`ready`、`applying`、`stopping` 和 `failed` 状态，并为每个状态定义专属字段。按后端串行化连接变更。测试和探测必须有截止时间并支持取消；重复提交应合并到活动转换，或被拒绝。

尽可能在停用当前描述符之前验证候选项。若托管目标需要启动，为满足单实例约束，应先停止原有受管服务器再启动替代项。切换前显示繁忙会话、排队派发、待处理审批和其他客户端。可延迟至空闲，也可由用户明确决定停止并切换；保留原身份下的草稿和排队意图，绝不隐式发送给替代项。

切换期间暂停派发；由各自归属方排空/取消进行中的工作，使 epoch 失效，停止受管资源，并绑定已验证的替代项。停止后若失败，进入可见的失败状态，并提供明确返回先前保存目标的操作。外部进程保持运行。清理失败时，在进程归属得到解决之前禁止再次启动受管进程。

有限重试可以重连同一个已选端点，或按已显示的策略重启同一个受管可执行文件。重试不得更改模式、可执行文件、端点配置或兼容配置。本里程碑不提供自动回退到其他模式。

## 3.3 重载与释放

以下路径定义 OpenCode 行为。CAgent 配置／重载在自己的作用范围和结果契约通过验证前保持禁用；OpenCode dispose 路由和进程重启均不能作为 CAgent 的回退方式。

应用前说明操作的实际效果：实时应用配置、按目录实例重载、全服务器实例重载或受管进程重启。设置归属方报告变更是否待应用；仅 HTTP 响应成功不应清除待应用状态。

| 所选路径 | 必需行为 |
| --- | --- |
| 外部服务器 | 使用已解析配置经过验证的 dispose 操作及其作用范围，然后探测并重新加载权威配置/目录/会话状态。绝不重启或杀死外部进程。 |
| 托管服务器命令 | 将重载视为服务器模式下按配置选择的实例 dispose。进程重启是独立的可见操作，用于启动配置/二进制变更或用户明确请求。 |
| PATH、已配置可执行文件、捆绑可执行文件 | 在需要时保留现有受管进程重启路径。对已经支持实时应用的变更，保留 OC2 监视配置应用行为。 |

连接 epoch 与目录实例有效性必须分开处理。端点、配置或受管进程被替换时，或经验证的操作确实要求全局释放时，才使连接 epoch 失效。按目录释放复用现有目录生命周期：拒绝该目录旧实例的结果，并在重载后恢复该目录订阅。保留其他所有目录的活动、请求和审批。目录重载不得通过全局锁暂停整个后端；全局/配置切换才可暂停全域。缺少目录 dispose 能力时不得悄悄扩大为全局释放。启用任何路径前，分别验证 OC1、OC2 和 Legacy 的实际方法、路由、请求体、响应和作用范围；历史 SDK 方法名本身不足以构成证据。

dispose 前获取对应范围的转换锁并检查活动状态。仅连接 epoch 变化时才重连数据流；目录重载只恢复该目录订阅并刷新其权威状态。超时或响应不明确时保留待应用状态并报告结果不确定。明确重试前重新探测；不得盲目重复可能已完成的破坏性操作。应用失败时不得声称配置为空或已应用。

## 3.4 原生菜单本地化

使用生效的应用语言翻译 Electron 应用、托盘和网页内容上下文菜单，包括 Electron role 周围的自定义标签。语言资源由原生代码的归属方管理，并且只能通过既有桥接传递经过验证的 locale。语言变更时重建菜单，同时保留操作、平台快捷键、勾选/禁用状态和窗口归属。窗口语言冲突时，原生应用/托盘菜单使用应用偏好；特定窗口的上下文菜单使用该窗口生效的语言。

在 Windows 和 macOS 上验证简体中文与英语；Linux 托盘行为必须明确测试或标记为未验证。共享应用内菜单保留现有本地化；浏览器/VS Code 宿主自有菜单不受 Electron 控制。

## 3.5 持久分支上下文

对于由 Git 管理的会话或草稿，无论工作状态面板是否显示，都要在标题旁或下方显示其当前仓库/工作树分支。手机和平板使用紧凑且持续可见的分支标签，完整名称可通过激活/焦点查看。标签可以省略显示部分字符；面板不能让分支完全不可见。

解析实际会话/草稿目录，而不是全局选中的项目。Detached HEAD 显示短提交标签。空仓库和非 Git 目录要有诚实且不同的状态。加载中或读取失败时，不得把缓存分支显示成最新值。现有会话保留其目录；刷新不会检出分支，也不会移动会话。运行时或目录切换必须拒绝过期结果。

## 3.6 显式刷新草稿分支

在草稿目标/分支选择器旁添加可访问的刷新操作。绕过常规 TTL，针对已捕获的目标目录同时请求当前 Git 状态和分支/工作树选项。一次刷新进行中时，重复点击应合并；目标变更时取消或使其结果失效。

显示刷新中、成功和可重试错误状态。普通刷新失败时保留旧数据并提示其已过期。如果当前检出状态由外部改变，显示新的当前分支。如果显式选择的新工作树/分支仍存在，则保留选择；若目标已消失或无法解析，则要求重新选择并禁用发送。保留草稿文本和附件。仅在目标本身正在变化时暂挂依赖目标的发送；目标仍有效时，刷新错误本身不阻止发送，也不要求额外确认。

## 3.7 有效快捷键提示

通过一个共享的操作提示 API/组件使用现有快捷键注册表和显示格式化器。它读取生效的自定义绑定及平台信息，包括已禁用/未绑定的操作。将其用于新建会话、侧边栏和焦点控件、工作区导航、绑定了快捷键的草稿刷新，以及其他已关联注册命令的按钮。实现期间维护有限的操作到控件覆盖清单。

快捷键变更时更新提示；键盘焦点和悬停时都显示提示。操作标签在触屏设备上仍须易懂。不得为未绑定的操作编造快捷键，也不得覆盖原生/操作系统拥有的绑定。显示的绑定和实际命令处理程序必须共享同一个操作身份。

## 运行时职责

| 运行时 | 必需结果 |
| --- | --- |
| Web | 服务端管理连接/配置/设置和自主工作。经过认证的 UI 可以检查并更改受支持模式；缺少捆绑文件/原生路径选择器时须明确显示不可用状态。 |
| Electron | 进程内 web 后端管理所有协议。主进程/preload 管理原生菜单、可执行文件选择和打包进程生命周期。其他窗口使用同一本地描述符，或使用各自选定的远程后端。 |
| VS Code | 扩展宿主管理连接/配置和进程生命周期；webview、消息和 SSE 桥接保持一致。扩展不可用的模式要明确禁用。不承诺提供 Electron 菜单。 |
| 托管移动端 | 共享服务端描述符/设置及分支/刷新流程。服务端路径不得指向手机文件系统。触屏标签保持可用。 |
| Capacitor | 先选择 OpenChamber 宿主，再使用该宿主的模式/配置。设备上不启动本地 OpenCode 进程或捆绑文件。重连时丢弃过期宿主/配置状态。 |
