# OpenCode 1.2.27 Legacy 规范

> 中文审阅与归档副本。英文交接源：[英文原文](../OPENCODE-LEGACY-1.2.27-SPEC.md)。同步与交接规则见 [README](README.md)。

状态：计划中，2026-10-08。精确版本 wire 契约和现场验收仍待采集。
上级文档：[OpenCode 集成规范](OPENCODE-INTEGRATION-SPEC.md)。

## 兼容承诺

相关中文文档：[DEV-PLAN](DEV-PLAN.md)、[PLAN](PLAN.md)、[双内核架构](DUAL-KERNEL-ARCHITECTURE.md)、[集成规范](OPENCODE-INTEGRATION-SPEC.md)、[Legacy 规范](OPENCODE-LEGACY-1.2.27-SPEC.md)、[集成里程碑](OPENCODE-INTEGRATION-MILESTONES.md)、[集成审计](OPENCODE-INTEGRATION-AUDIT.md)。

为无法升级 OpenCode 的安装提供专用的 `Legacy 1.2.27` 配置。系统根据经过验证的服务器身份自动选择，或由用户手动选择。所有接触 OpenCode 的 OpenChamber 操作都使用此配置的契约，包括浏览器请求、服务端任务、事件、配置/认证/插件写入和宿主桥接。

现有 OC1 适配器及其针对较新运行时的测试只是起始实现，不能视为 1.2.27 验收。早期文档将精确版本测试推迟到初始双内核交付之后。本里程碑仅对其 Legacy 交付项取代该延期决定：不能依据较新 OC1 二进制上的测试验收。OC1 和 OC2 仍受支持，并保留各自回归门槛。

本配置覆盖 OpenChamber 实际使用的所有 OpenCode 操作，而非 OpenCode 产品中未使用的每个端点。清单必须包含动态拼接的请求和注入的插件调用。OpenChamber 自有的文件系统/Git 路由继续使用各自契约；其中任何 OpenCode 交互仍使用已选配置。

## 选择与身份

请求的选择和解析后的配置分别持久化。可选项为 Auto、OC1、OC2 和 Legacy 1.2.27。连接设置中显示检测到的版本、已选配置、版本来源和任何验证限制。

| 请求的选择和证据 | 结果 |
| --- | --- |
| Auto；已验证的稳定版本 1.2.27 | 在任何功能请求前解析 OC1 代际和 Legacy 配置。 |
| OC1；已验证的稳定版本 1.2.27 | 在 OC1 内解析为 Legacy。选择代际不能绕过精确版本适配。 |
| Auto/OC1；其他受支持的 OC1 版本 | 使用现有 OC1 配置及其显式能力。不得声称已验收 Legacy。 |
| Auto/OC2；受支持的 OC2 版本 | 使用 OC2。保留当前最低版本和能力检查。 |
| Legacy；已验证的稳定版本 1.2.27 | 选择 Legacy 并验证其只读契约检查。 |
| Legacy；版本缺失但端点有响应 | 仅在 Legacy 只读契约检查通过后，允许用户明确声明。标记版本为用户声明/未验证；绝不可称为自动检测或精确版本验收。 |
| 显式选择与报告版本或契约矛盾 | 显示不匹配并要求修正；不得自动切换配置。 |
| Auto；版本缺失、探测矛盾、认证失败或服务器不可达 | 区分这些状态并要求修正/手动选择。不得根据失败的 SDK 调用猜测配置。 |

比较精确稳定版本时，先规范化前导 `v` 和构建元数据。行为不兼容的 `1.2.27` 预发布版或分支不得自动视为经过测试的稳定版本。应单独记录并验证该分支。只在已选端点上执行探测；连接发现不得搜索其他服务器。

现有 health/info 探测归属方必须依据 INT-00L（Legacy 专用预检）中经过验证的 1.2.27 证据，定义 Legacy 只读检查集合。检查应使用可用的身份/目录/读取契约，不能创建会话、释放实例或写入配置。若端点不报告版本，仅检查健康状态并不足够。考虑手动覆盖能否使用之前，先显示认证失败。

对于受管进程，将所选可执行文件的版本与响应端点的版本比较。解析完成前不要加载仅适用于现代版本的插件。对外部服务器，以远端身份为准；本机已安装 CLI 不能证明远端版本。选择 Legacy 不会下载、替换或降级二进制文件。

在同一 URL 上选择其他配置时，运行时 epoch 递增。每个请求、排队发送、事件流和延迟写入都要捕获配置/epoch。废弃旧客户端、停止旧订阅并拒绝过期完成结果。后端切换不得悄悄把另一配置下排队的工作转换过来。

## 操作归属

在现有 OC1 UI 和服务端边界下放置 Legacy 专属编解码器和操作实现。只有在验证请求和响应契约与 1.2.27 一致后，才复用现有 OC1 操作。不要复制整套 OC1 服务，也不要把版本比较散落到 UI 组件中。

若官方 SDK 能保留已验证请求，则通过范围明确的兼容包装器使用它。当前 SDK 输出较新格式时，在同一边界使用有文档说明的 SDK gap/版本包装器。记录方法、路径、请求头、查询、请求体、错误和取消行为。针对当前 SDK 声明的类型断言不能证明旧服务器契约。

能力结果分为 supported、adapted 或 unsupported，并附证据和原因。尚未验证的操作对实验配置保持阻塞，不得默认通过现代 OC1 发送。即便调用方绕过 UI 控件，不支持的调用也必须在服务/宿主边界、网络或文件系统副作用发生前失败。

完整 Legacy 验收必须通过下述基准用户旅程。不能用能力标签丢弃核心聊天、权限/问题、停止、历史或现有自动化功能。如果证据证明所请求功能在 1.2.27 上确实无法实现，则记录具体限制，并在接受该里程碑前确定产品处置。

## 契约采集与不确定项

固定精确版本的上游 1.2.27 源码／接口 schema 及实际 1.2.27 可执行文件，并记录来源和摘要。在隔离数据目录中采集已脱敏的请求、响应、失败封装和 SSE。保留原始字段结构、状态码和顺序，同时移除凭据和用户内容。将样本关联到可执行文件身份和复现命令。

本次规划没有启动 1.2.27，也没有获取到可用的固定版本接口 schema。官方 raw OpenAPI URL 返回 cache miss。不得从现代 OC1 类型补全缺失契约。以下均为待验证问题，并非已确定的不兼容：

- Shell 返回裸消息，还是 message/parts 封装。
- Diff 数据包含前后文本、patch 文本，还是多个变体。
- 校验错误使用 success/data/errors 封装，还是其他格式。
- 实际存在的 permission/question 字段和事件载荷。
- 是否存在 replay 标识符，以及恢复时是否保证顺序。
- 服务端是否支持幂等键及其保留期，或能否通过请求 ID 可靠查询请求结果。
- 存在哪些 dispose 方法/作用范围、响应格式和配置应用效果。
- 旧二进制接受哪些元数据、插件、OAuth、模型选择和较新操作字段。

证据来源优先级为精确版本服务端／源码／接口 schema，其次是可执行文件样本和回归测试样本。仅从现代 SDK 类型推导的样本不能作为精确版本参考。

### 派发结果契约

提交派发前，通过现有归属方持久化意图和尝试记录。状态区分 `pending`（待发送）、`accepted`（已接受）、`unknown`（结果未知）以及终态 `completed`（完成）或 `failed`（失败）。复用现有队列/任务归属方，不另建派发引擎。

服务器已接受请求但响应丢失，或客户端在提交期间崩溃时，恢复后将尝试标为 `unknown`。不得自动重发，也不得报告成功或失败。自动对账需要可靠的请求 ID 结果查询。自动重发需要精确 1.2.27 证据，证明幂等键仍在保留期内，或权威查询证明原请求未被接受且之后也不会执行。仅查询不到结果并不足够。仅凭时间或文本匹配无法判断请求是否已执行。

缺少上述证据时，将受影响任务保留为可核对、等待或由用户明确重发。重发前告知用户原请求可能已经执行，再次发送可能重复产生副作用。其他任务继续运行。测试正常单次派发、请求已接受但响应丢失、发送期间崩溃并重启、重复触发，以及任何已证实的服务端去重行为。没有能证明该能力的证据，不得声称恰好派发一次。

## 恢复、配置与存储

不得假设 SSE 支持 replay。依据精确版本证据实现恢复行为；若没有 replay 或其不完整，则通过权威读取协调特定目录/会话的消息、状态和待处理 permission/question。按活动目录/会话合并恢复请求，保留其他无关作用域的成功结果并拒绝过期 epoch。恢复失败时，不得清除待处理审批，也不得宣称繁忙会话已空闲。

根据实际终态消息/状态证据推导完成。HTTP 接受、空 delta、断连或经过一段时间都不能结束轮次。在配置边界规范化已知错误格式，并在不泄漏敏感载荷的前提下保留可采取行动的错误信息。

只使用经过 1.2.27 验证的配置字段、凭据和插件 hooks。明确外部配置归属：不得写入本地配置文件后声称远程服务器已应用。远程配置写入不受支持时，返回可执行的限制说明。受管 Legacy 的本地数据使用由版本/配置拥有的作用域，避免现代/OC2 迁移改变兼容性。既有外部路径仍归用户所有；不得自动跨配置迁移数据。

OpenChamber 只有通过明确归属且经过往返测试的记录，才能存储自身补充元数据。不得暗示旧服务器持久化了它忽略的字段。在较新运行时使用同一存储前保护现有数据；切换配置不是数据库降级策略。

按[集成 dispose 契约](OPENCODE-INTEGRATION-SPEC.md#33-reload-and-dispose)执行重载：目录变更默认使用目录级 dispose；只有变更确实需要全局作用范围且用户明确操作时才提供全局 dispose。如果只存在全局 dispose，应在执行前说明作用范围和对活动工作的影响。目录重载不受支持时应如实报告，不得悄悄扩大到全局范围。

## 验收矩阵

| 门槛 | 必需证据 |
| --- | --- |
| 精确身份 | 真实稳定版 OpenCode 1.2.27 版本、可执行文件/源码来源和摘要；分别验证自动选择和手动选择。手动未验证模式不能满足此门槛。 |
| 核心会话 | 连接、列出/创建/打开历史、文本和附件提示、工具活动、permission/question 回复、停止、命令/shell、fork/compact/diff/revert、完成和重新打开。 |
| 失败与恢复 | 错误凭据、服务器不可用、响应/事件格式错误、数据流中断、服务器重启、待处理决策恢复以及配置切换后的过期结果。 |
| 无人值守操作 | UI 关闭时运行 queue 和计划提示以及 assist/goal；派发意图和尝试记录可持久化；没有已证实的去重/结果查询能力时，结果不明的请求保持未知；元数据/状态正确持久化。测试正常单次派发、已接受但无响应、发送期间崩溃并重启、重复触发和已验证的去重行为。 |
| 设置与生命周期 | 在支持范围内写入 provider/agent/MCP/skill/config、生成插件加载、dispose/apply、受管启动/退出和外部归属。 |
| 隔离 | Legacy ↔ 当前 OC1 ↔ OC2，包括同一端点改用新配置；会话/cache/auth 作用域分离，不发生意外迁移或跨配置写入。 |
| 宿主 | 真实 web 和 Windows portable 流程、VS Code 桥接/运行时检查、托管移动端和 Capacitor 连接旅程。明确记录未测试的原生平台；未测试的宿主行保持未完成。 |

后续分组仍禁用时，里程碑可以交付内部实验配置。只有所有必需分组和宿主门槛均已验收，或维护者明确缩小本次发布承诺后，发布才能宣传完整 Legacy 支持。缺少 1.2.27 可执行文件/端点会阻止精确版本验收，但不妨碍完成这些规划文档。
