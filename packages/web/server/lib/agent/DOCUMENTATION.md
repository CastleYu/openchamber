# Agent dispatch contracts

This module implements part of CA-01. The server reserves authenticated owned routes, but its binding remains inactive and CAgent is unavailable. Current OpenCode runtime behavior is unchanged. The remaining migration is tracked in [the execution checkpoint](../../../../../docs/maintenance/CAGENT-EXECUTION.md).

`constants.js` owns backend-family, support, operation and refusal constants. `dispatcher.d.ts` defines runtime-neutral requests/results for the 22 effect/read operations consumed by the host inventory. Identity capture is the 23rd host operation and belongs to the dispatcher rather than the adapter. Workspace IDs are backend-owned identifiers, never implicit local directories. No SDK raw payload is required by these contracts. More detailed message/decision contracts and UI operations must be added from consumer semantics before their migration is accepted.

`createAgentDispatcher({ getBinding, attempts })` reads host authority at call time. The adapter supplies handlers and candidate support; a separate host-owned acceptance record grants access for an exact adapter and capability revision. A supported declaration without evidence and matching acceptance is refused. Unverified, unsupported, auth failure, not-ready and missing-handler outcomes remain distinct.

`schemas.js` strictly parses inputs and outputs for all 22 operations. Dispatch passes the parsed request copy to the handler and returns the parsed result copy. Missing identifiers, invalid enums and extra keys are rejected. It captures backend identity and checks it again before entering a handler. After an identity change, reads reject stale data. An entered mutation reports an unknown outcome if its handler fails, its result is malformed, or the identity changes. Read failures without an identity change propagate to the owning boundary. This module performs no retry, fallback or cross-backend replay. Production mutations still require an accepted binding and migrated consumers.

`createAgentDispatcher` now accepts a host-owned `attempts` store. All 11 mutation inputs require a request ID. Without storage, mutations are refused before entering a handler. `attempts.js` exclusively reserves an intent file and syncs its unknown record before dispatch. The key uses backend family, connection ID and request ID; epoch or adapter revision changes cannot permit resend of an existing intent. Concurrent reservations have one winner. Storage failure prevents dispatch and retains any incomplete reservation.

After reservation, the dispatcher rechecks authority. Revocation before handler entry records `not-sent`. Entered handler failures, malformed or mismatched receipts, unknown receipts and failed final persistence return `unknown-outcome`. Confirmed results record `accepted` or `complete`; acceptance does not establish completion. Final authority is rechecked after persistence. The ledger stores identity, operation, request ID and attempt state, without prompts, credentials or results. A restarted reader returns the recorded history, never live activity. Corrupt and unavailable storage are errors, not missing records. There is no automatic resend, deletion or retention policy. Native file sync is tested for process restart; power-loss durability and Windows ACL isolation are not established by these tests. Production composition supplies a lazy store under its existing data directory; no record is created without an accepted dispatch.

`readAttempt(expectedIdentity, requestID)` is host-owned history access, separate from the adapter operation inventory. It requires an authorized, ready binding and exact current identity before and after reading. A changed identity or revoked access rejects the result. It does not require current write capability, so a disabled operation can still have its recorded attempt inspected. The record retains its original epoch and revisions. A missing record returns explicit null; storage errors propagate. This lookup does not query CAgent or prove that an accepted request completed.

Host composition must supply normalized, immutable bindings. It must keep activation records and handler registration outside the environment-local agent's writable files. A manifest cannot construct this authority directly. Each handler must also parse its real server's response before projecting domain data. These schemas validate the neutral contract, not undocumented CAgent wire semantics.

`routes.js` owns GET `/api/agent-backend/runtime`, POST `/api/agent-backend/dispatch` and POST `/api/agent-backend/attempt`. Server composition mounts them after the existing API authentication gate and before generic OpenCode proxy registration. Dispatch and lookup require an exact expected identity. Both POST routes own their JSON parsers. Lookup carries the request ID in its strict body, never a URL. The routes expose fixed host-owned refusal codes instead of exception text: duplicate attempt 409, corrupt/unavailable storage 503 and entered unknown outcome 409. Unknown paths and methods terminate inside this namespace. Accepted bindings can dispatch durable mutations through the same host guard as direct callers. Without a store, accepted writes return `write-unavailable`. The current production dispatcher has no binding, so all three routes return `unavailable`. No activation setting or adapter manifest can change that yet.

| Runtime | Current behavior |
| --- | --- |
| Web | Owned routes and durable storage are composed with an inactive binding. Identity, dispatch and lookup return 503 `unavailable`. CAgent unavailable. |
| Electron | Same in-process web backend and refusals. No native protocol implementation. CAgent unavailable. |
| VS Code | Webview and extension-host generic proxy refuse owned agent routes with 501 `unsupported-runtime`; no OpenCode forwarding. CAgent unavailable. |
| Hosted mobile | Selected OpenChamber server exposes the same inactive routes and refusals. CAgent unavailable. |
| Capacitor | Selected OpenChamber server exposes the same inactive routes and refusals. CAgent unavailable. |

Focused validation uses the package Vitest runner on `server/lib/agent/{attempts,dispatcher,schemas,routes}.test.js` and `contracts.test.ts`. HTTP tests use real Express requests with a test authentication gate and synthetic accepted bindings. They cover body parsing, refusal codes, identity, malformed requests/results, durable mutation/lookup and proxy isolation. They do not start the full production server or establish real CAgent compatibility. VS Code's `src/bridge-proxy-runtime.test.js` checks refusal before local or upstream forwarding. Directly compile `contracts.test.ts` with the installed TypeScript compiler as well. Its compile-only calls check operation-specific results, complete operation-key coverage and rejection of missing workspace/request identity and unknown operations. The web workspace's normal type-check includes UI/src, not server declaration files.
